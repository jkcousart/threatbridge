# Security policy

## Supported code

Security fixes are developed against the current default development line. No long-term support
or public release schedule has been established.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities, credentials, source records, or deployment details in
a public issue. Before publication, the repository owner must configure and verify a private
security-reporting channel, such as the hosting provider's private security-advisory feature.

Until that channel is configured, stop and contact the repository owner through an independently
verified private channel. Do not send secrets or complete evidence records in the initial report.
Include only the affected version, impact, minimal reproduction steps, and whether exploitation is
known.

## Response expectations

No response-time service level is promised before a maintained public release exists. Reporters
should receive an acknowledgement, a safe coordination path, and disclosure guidance once the
private channel is operational.

## Security boundaries

ThreatBridge is not currently production-ready or public-release-ready. See
[`docs/public-release-readiness.md`](docs/public-release-readiness.md) and
[`docs/security-architecture.md`](docs/security-architecture.md) for current controls and limits.
